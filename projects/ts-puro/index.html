O tipo nasce do esquema, não do seu teclado

Mude o esquema ao lado e veja o tipo TypeScript se reescrever sozinho. Não há interface escrita à mão em lugar nenhum: o tipo é derivado da estrutura por tipos condicionais e mapeados. E não é simulação — é o compilador do TypeScript de verdade, rodando nesta página.

TypeScript 5 tipos condicionais e mapeados infer compilador rodando no navegador 0 dependências na biblioteca
Por que este projeto O sistema de tipos do TypeScript é uma linguagem própria, e quase todo mundo usa só a parte fácil dela. Derivar o tipo a partir do esquema — inclusive transformar campo opcional em chave opcional — é o truque que sustenta o Zod e o Prisma. É a diferença entre usar TypeScript e programar o compilador.

A biblioteca

A parte que faz o tipo aparecer sozinho são estas três linhas. O resto é validação comum. 

type Inferir<E> = E extends Esquema<infer T> ? T : never;

type ChavesOpcionais<F> = { [K in keyof F]: undefined extends Inferir<F[K]> ? K : never }[keyof F];

type SaidaObjeto<F> = { [K in ChavesExigidas<F>]: Inferir<F[K]> } & { [K in ChavesOpcionais<F>]?: Inferir<F[K]> };

infer T captura o tipo de dentro de Esquema<T>. ChavesOpcionais percorre os campos, testa quais aceitam undefined e devolve só os nomes deles. O resultado: um campo marcado com opcional() vira chave opcional no tipo — e não string | undefined, que ainda obrigaria a escrever a chave.
