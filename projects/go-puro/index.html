Goroutines de verdade, acontecendo na sua frente

Isto não é uma animação imitando concorrência. São goroutines de verdade lendo de um channel de verdade, compiladas para WebAssembly. Mexa no ritmo de produção e no tamanho da fila e veja o sistema saturar, descartar tarefa e devolver a pressão para quem produz.

Go 1.23 GOOS=js GOARCH=wasm goroutines + channels select, WaitGroup, atomic roda no navegador
Por que este projeto Concorrência é a razão de existir do Go. Em vez de explicar channel num texto, o visitante mexe nos parâmetros e vê o escalonador reagindo: fila cheia, worker ocioso, tarefa descartada. São os três estados que todo sistema de fila real vive — e a diferença entre eles é uma linha de código.

O que observar

Fila em zero. O channel deixa de ter buffer e vira síncrono: o produtor só entrega quando existe um worker pronto para receber naquele instante. Nada fica guardado — ou alguém pega agora, ou a tarefa se perde.

Produção mais rápida que o consumo. A fila enche, e a partir daí toda tarefa nova é descartada. Isso é uma escolha explícita no código: o select com default torna o envio não-bloqueante. Sem o default, o produtor esperaria — que é o outro comportamento possível, o backpressure.

Workers ociosos com fila vazia. Uma goroutine parada num channel não consome CPU: o escalonador simplesmente não a agenda. É isso que permite ter centenas de milhares delas — coisa impensável com uma thread do sistema para cada.

O preço: este WebAssembly tem 2,4 MB, enquanto o ray tracer em C ao lado tem 17 KB. A diferença não é o meu código — é que o Go embarca o próprio escalonador e o coletor de lixo dentro do binário. É exatamente o que torna tudo acima possível de escrever em poucas linhas.
